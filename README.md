# СИГМА — два бота для такси/доставки

Два Telegram-бота, которые работают в паре:

| Бот | Для кого | Что делает |
| --- | --- | --- |
| **Бот-заказчик** (`CLIENT_BOT_TOKEN`) | клиенты | принимает заказ, автоматически публикует его в чат водителей, присылает ФИО и телефон того, кто взял |
| **Бот-диспетчер** (`GROUP_BOT_TOKEN`) | чат водителей | публикует карточку с кнопкой **«✅ Принять заказ»**, сам обновляет статус, ведёт статистику |

Без цен и тарифов. Всё на стандартной библиотеке Python + SQLite, без зависимостей
и без вебхуков. Один процесс опрашивает оба бота параллельно.

## Как это выглядит

### Клиент

1. `/start` → **«🚕 Заказать такси»**.
2. Откуда → куда → комментарий (`-` пропустить) → телефон (`-` пропустить).
3. Проверяет карточку → **«✅ Отправить»**.
4. Заказ **сразу автоматически** улетает в чат водителей, клиент видит «Ищем водителя…».
5. После принятия карточка меняется на ФИО и телефон водителя.

### Чат водителей

Карточка строго по форме — клиент и куда, плюс кнопка:

```
🚕 НОВЫЙ ЗАКАЗ #0001

👤 Клиент: Аня (@anya)
📞 Телефон: +79990000000

🏁 Куда: ул. Мира 5
📍 Откуда: ул. Ленина 1
📝 Комментарий: подъезд 2

🟡 Ждёт водителя
Нажмите «Принять заказ»

[✅ Принять заказ]
```

После нажатия карточка **сама** обновляется у всех:

```
━━━━━━━━━━━━━━━
✅ Принял: Петров Пётр
📞 +79991112233
🕒 17:42

🟢 Принят

[🚗 Выехал к клиенту]
[❌ Отказаться]
```

Дальше: **«🚗 Выехал к клиенту»** → **«🏁 Доставил заказ»**. Клиент получает
уведомление на каждом шаге. Всё автоматически, без участия диспетчера.

## Защита от повторных нажатий

Три уровня:

1. **Атомарный SQL** — `UPDATE ... WHERE id=? AND status IN ('new','searching')`.
   Даже если два водителя жмут «Принять» в одну секунду, меняется ровно одна строка.
2. **ActionGuard** — один и тот же callback (`заказ + действие`) в течение 4 секунд
   обрабатывается один раз, второй клик получает «Уже обрабатывается…».
   Плюс блокировка на заказ: все действия по нему идут строго по очереди.
3. **Проверка статуса** — повторное «Доставил»/«Отменил» на закрытом заказе
   отклоняется, а не перезаписывает данные.

Покрыто тестами: 8 потоков жмут «Принять» — побеждает один; тройной клик по
«Принять» создаёт один заказ; двойной «Отправить» — тоже один.

**«📦 Последние заказы»**.

## Автоматика

- Публикация в чат — сразу после «Отправить», в отдельном потоке.
- Статусы обновляются автоматически по нажатиям водителей.
- **Автоотмена**: заказ, который никто не взял за `ORDER_TTL_MINUTES` (по умолчанию
  30 мин), отменяется сам, клиенту приходит уведомление.
- Проверка автоотмены идёт в фоне, не чаще раза в 15 секунд.

## Быстрый старт

### 1. Создайте двух ботов

В Telegram у **@BotFather**:

1. `/newbot` → `Сигма Заказ` → токен №1.
2. `/newbot` → `Сигма Диспетчер` → токен №2.

### 2. Настройте `.env`

```bash
cd sigma-bot
cp .env.example .env
nano .env
```

Минимум:

```
CLIENT_BOT_TOKEN=...
GROUP_BOT_TOKEN=...
GROUP_CHAT_ID=-1001234567890
ADMIN_CODE=свой-секретный-код
```

### 3. Узнайте `GROUP_CHAT_ID`

1. Добавьте бота-диспетчера в чат водителей.
2. Напишите в чате `/id` — бот ответит `ID чата: -100...`.
3. Впишите число в `.env`.

### 4. Запуск

```bash
./run.sh
```

или через Docker:

```bash
docker compose up -d --build
```

Для бота-диспетчера в @BotFather → `/setprivacy` → **Disable**, чтобы он видел
команды и ответы в группе.

## Статусы заказа

| Статус | Что значит |
| --- | --- |
| `new` | создан, готовится к отправке |
| `searching` | опубликован, ждёт водителя |
| `accepted` | водитель назначен |
| `on_way` | водитель выехал |
| `done` | доставлено |
| `cancelled` | отменён клиентом, водителем или автоматически |

## Пересылка заказов из других чатов

- Добавь бота-диспетчера в чат, откуда идут заказы.
- Ответь командой `/forward` на сообщение с заказом — бот перешлёт его в чат водителей.
